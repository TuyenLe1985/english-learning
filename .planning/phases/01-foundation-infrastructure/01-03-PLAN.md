    This is a fresh database — no existing migrations. Run migrate dev to create the initial migration and apply it.

    PREREQUISITE: Docker must be running with postgres container healthy. Verify with: docker compose ps postgres | grep "(healthy)". If not healthy, run docker compose up -d postgres and wait 30 seconds.

    STEP 1 — Generate Prisma client first:
    Run: pnpm --filter @repo/database run db:generate
    This generates packages/database/generated/client/ from the schema. Required before running migrations because the Prisma CLI reads the schema from disk but the client output directory must exist.

    STEP 2 — Run the initial migration:
    Run: cd packages/database && DATABASE_URL=postgresql://postgres:CHANGE_ME@localhost:5432/english_learning npx prisma migrate dev --name init --schema ./prisma/schema.prisma
    Or if DATABASE_URL is in root .env: pnpm --filter @repo/database run db:migrate -- --name init

    This creates packages/database/prisma/migrations/YYYYMMDDHHMMSS_init/migration.sql with all CREATE TABLE statements.

    STEP 3 — Verify tables were created:
    Run: psql -h localhost -U postgres -d english_learning -c "\dt" 2>/dev/null | grep -E "(User|SrsCard|VocabularyWord|ReadingPassage|ListeningContent|QuizSession)"
    Or via docker: docker exec el_postgres psql -U postgres -d english_learning -c "\dt"

    The migration folder (packages/database/prisma/migrations/) must be committed to git — it is NOT gitignored. Migration SQL is the source of truth for schema evolution.

    If migration fails: most likely causes are (a) DATABASE_URL env var not set — check .env exists and has correct value, (b) Postgres container not running — docker compose up -d postgres, (c) schema validation error — rerun prisma validate first, (d) Prisma 7 was installed — check `pnpm --filter @repo/database exec prisma --version` shows "6.x.x".
