<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → NestJS API | Bearer JWE token crosses; must be decrypted and validated, never trusted raw |
| Next.js → PostgreSQL | PrismaAdapter writes user/account records |
| npm registry → build | package installs (supply chain) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Spoofing | JwtAuthGuard token validation | mitigate | Decrypt with @auth/core decode using NEXTAUTH_SECRET; reject on any decode failure (RESEARCH Pattern 2) |
| T-02-02 | Information Disclosure | NEXTAUTH_SECRET in env | mitigate | Read only via ConfigService from env; never hardcode (RESEARCH Pitfall 3 / Anti-Patterns) |
| T-02-03 | Tampering | JWT payload claims (role/cefrLevel) | accept | Payload integrity guaranteed by JWE encryption+MAC; tampering invalidates the token |
| T-02-SC | Tampering | npm installs (next-auth, @auth/core, passport-jwt, bcrypt) | mitigate | All [ASSUMED] per audit; blocking human-verify checkpoint (Task 2.5) before trusting |
</threat_model>
