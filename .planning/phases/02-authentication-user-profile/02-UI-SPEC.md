## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, inline tag padding |
| sm | 8px | Input inner padding (vertical), badge padding |
| md | 16px | Card body padding, form field vertical gap |
| lg | 24px | Card padding (horizontal), section vertical gap |
| xl | 32px | Auth page content max-width padding |
| 2xl | 48px | Vertical space between form sections |
| 3xl | 64px | Auth page top/bottom margin on centered card |

Exceptions:
- Touch targets for interactive icons (avatar edit button, resend link): minimum 44px height — use `min-h-[44px]` Tailwind class.
- Rate-limit countdown timer inline text: no additional spacing beyond the surrounding paragraph.

## Typography

All sizes use Inter. Two weights only: 400 (regular) and 600 (semibold).

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 16px | 400 | 1.5 | Form labels, input placeholder, paragraph text, email copy descriptions |
| Label | 14px | 600 | 1.4 | Form field labels (`<Label>` component), badge text, helper text below inputs |
| Heading | 24px | 600 | 1.2 | Page title (e.g. "Sign in to your account"), section headers on profile page |
| Display | 32px | 600 | 1.15 | Used nowhere in Phase 2 — reserved for dashboard; do not introduce here |

**Font loading (layout.tsx):**

```tsx
import { Inter } from 'next/font/google';
const inter = Inter({ subsets: ['latin'], variable: '--font-inter' });
```

Apply `inter.variable` on `<html>` and set `font-family: var(--font-inter), system-ui, sans-serif` in CSS.

## Color

Uses shadcn zinc CSS variable tokens. All values below are the zinc palette defaults from `npx shadcn init`.

| Role | CSS Variable | Hex (light mode) | Usage |
|------|-------------|------------------|-------|
| Dominant (60%) | `--background` | `#ffffff` (zinc-50) | Page background, auth card background |
| Secondary (30%) | `--card` / `--muted` | `#f4f4f5` (zinc-100) | Card surface, input background on focus, verify-email notice box |
| Accent (10%) | `--primary` | `#18181b` (zinc-900) | See reserved list below |
| Destructive | `--destructive` | `#ef4444` (red-500) | See destructive list below |

**Accent (`--primary` zinc-900) reserved for exactly these elements:**
1. Primary CTA buttons (Submit, Continue, Save changes)
2. Active/checked state on form controls
3. Focus ring on inputs and interactive controls
4. Resend email link text (to draw attention without additional color)

**Destructive (`--destructive` red-500) reserved for exactly these elements:**
1. "Delete account" button label text (deferred, but reserve the pattern now)
2. Error alert backgrounds for failed auth (wrong password, token expired)
3. Field-level validation error text below inputs

**CEFR level badge colors** (three distinct values, used only on the CEFR badge component):

| Level | Background | Text | Tailwind classes |
|-------|-----------|------|-----------------|
| B1 | `#dbeafe` (blue-100) | `#1d4ed8` (blue-700) | `bg-blue-100 text-blue-700` |
| B2 | `#d1fae5` (emerald-100) | `#065f46` (emerald-800) | `bg-emerald-100 text-emerald-800` |
| C1 | `#ede9fe` (violet-100) | `#5b21b6` (violet-800) | `bg-violet-100 text-violet-800` |

These three CEFR badge colors are the only non-shadcn colors introduced in Phase 2. They must be consistent across all phases of the app.

## Component Inventory

### Auth Layout Shell
- Route group: `(auth)` — centered single-column layout, no sidebar, no nav
- Max content width: 400px centered in viewport
- Background: `--background` (white)
- Card: shadcn `<Card>` with `p-8` (32px), `rounded-xl`, `shadow-sm`
- App logo/name: "English Learning" in 20px semibold above the card, links to `/`

### Login Page (`/login`)
- Page title: "Sign in to your account"
- Form fields: Email (`type="email"`), Password (`type="password"` with show/hide toggle)
- Primary CTA: `<Button variant="default" size="default">` full-width — "Sign in"
- Google OAuth button: `<Button variant="outline" size="default">` full-width — Google icon (lucide or inline SVG) + "Continue with Google"
- Divider: `<Separator>` with "or" label between the two button groups
- Footer link: "Don't have an account? Register" — 14px regular, `--muted-foreground`
- "Forgot password?" link: right-aligned below password field — 14px regular, `--primary`
- Error display: shadcn `<Alert variant="destructive">` below form heading, above fields — shown only on auth failure

### Register Page (`/register`)
- Page title: "Create your account"
- Form fields: Display name, Email (`type="email"`), Password (`type="password"` with show/hide toggle), Confirm password
- Password strength: no visual indicator in Phase 2 (deferred complexity)
- Primary CTA: `<Button variant="default" size="default">` full-width — "Create account"
- Google OAuth button: same as login, "Continue with Google"
- Footer link: "Already have an account? Sign in"
- Error display: shadcn `<Alert variant="destructive">` for API-level errors; inline `<p className="text-sm text-destructive">` for field-level validation

### Verify Email Page (`/verify-email`)
- Page title: "Check your inbox"
- Body copy: "We sent a verification link to **[email]**. Click the link to activate your account."
- Resend button: `<Button variant="outline" size="sm">` — "Resend verification email"
- Rate-limit state: When disabled (within 60s cooldown), button shows "Resend again in **Ns**" where N counts down in the button label. Button is `disabled` prop during cooldown.
- Max resends reached state: Replace button with inline text "Maximum resends reached. Wait 1 hour or contact support."
- No navigation away from this page until verified (no dashboard link)

### Reset Password — Request Page (`/reset-password`)
- Page title: "Reset your password"
- Subtitle: "Enter the email address on your account and we'll send you a reset link."
- Form field: Email only
- Primary CTA: full-width — "Send reset link"
- Success state: replace form with confirmation message — "If that email is registered, a reset link is on its way. Check your inbox." (never reveal whether email exists)
- Back link: "Back to sign in" — below CTA

### Reset Password — Confirm Page (`/reset-password/confirm`)
- Page title: "Choose a new password"
- Form fields: New password, Confirm new password
- Primary CTA: full-width — "Set new password"
- Expired token state: shadcn `<Alert variant="destructive">` — "This link has expired. Request a new one." with inline link "Request new reset link" pointing to `/reset-password`
- Success state: "Your password has been updated. Sign in with your new password." + "Go to sign in" button

### Profile Page (`/profile`)
- Layout: `(dashboard)` route group — full app chrome (nav + sidebar introduced in Phase 8; for Phase 2 use a minimal top bar with logo + sign-out button)
- Page title: "Your Profile" (24px heading)
- Two-column layout on `md+`: avatar column (left, 1/3 width) + details column (right, 2/3 width)
- Single column on mobile

**Avatar Section:**
- Display: `boring-avatars` `<Avatar>` component, size 96px (w-24 h-24), `variant="initials"`
- When custom avatar uploaded: show `<img>` in `rounded-full w-24 h-24 object-cover`
- Edit button: `<Button variant="ghost" size="sm">` overlaid at bottom-right of avatar — pencil icon + "Change photo"
- Clicking opens a file input (`accept="image/jpeg,image/png,image/webp"`)
- Upload progress: replace button with a spinner (`lucide-react Loader2` animated) during presigned URL fetch + direct upload
- Upload error: inline `<p className="text-sm text-destructive">` below avatar — "Upload failed. Max 2 MB, JPEG/PNG/WebP only."

**Details Section:**
- CEFR badge: shadcn `<Badge>` with custom colors from color contract — "B1 Intermediate" / "B2 Upper Intermediate" / "C1 Advanced"
  - Badge text format: `{level} {label}` — use these exact labels:
    - B1 → "B1 Intermediate"
    - B2 → "B2 Upper Intermediate"
    - C1 → "C1 Advanced"
- XP display: "1,240 XP" in 16px regular, muted foreground — below CEFR badge
- Registration date: "Member since June 2026" — 14px, muted foreground
- Display name field: editable inline — `<Input>` pre-filled with current name
- Email field: read-only `<Input disabled>` with lock icon — email cannot be changed in Phase 2
- Save button: `<Button variant="default" size="default">` — "Save changes" — only enabled when name field is dirty (changed from saved value)
- Success toast: shadcn `<Toast>` — "Profile updated" — shown after successful PATCH /api/users/me

## Interaction States

All interactive elements must implement these states. No state may be left unstyled.

| State | Pattern |
|-------|---------|
| Default | shadcn default variant styles |
| Hover | shadcn hover state (built-in via Radix) |
| Focus | 2px `ring-ring` ring with `ring-offset-2` — keyboard visible |
| Active / Pressed | `scale-[0.98]` via `active:scale-[0.98]` Tailwind |
| Disabled | `opacity-50 cursor-not-allowed` — shadcn default |
| Loading | Replace button text with `<Loader2 className="animate-spin h-4 w-4" />` — button stays full-width, no layout shift |
| Error (field) | Red border on input (`border-destructive`), red text below (`text-destructive text-sm`) |
| Error (page) | `<Alert variant="destructive">` above form |
| Success | `<Toast>` (bottom-right, auto-dismiss 4s) for mutations; confirmation message replaces form for one-way actions (verify, reset) |

## Accessibility Contract

- All form fields paired with `<Label htmlFor>` — no unlabeled inputs
- Error messages use `aria-describedby` linking input to error `<p>` — shadcn `<FormMessage>` handles this automatically
- Password show/hide toggle: `aria-label="Show password"` / `aria-label="Hide password"`
- Loading buttons: `aria-disabled="true"` + `aria-label="Signing in..."` during async submission
- CEFR badge: `aria-label="CEFR level: B2 Upper Intermediate"` — screen reader reads full label
- Avatar upload button: `aria-label="Change profile photo"`
- Focus trap: none needed for Phase 2 (no modals; all flows are full-page)
- Color contrast: shadcn zinc tokens pass WCAG AA at default sizes (verified in shadcn default theme)
- CEFR badge colors verified: blue-100/blue-700 = 5.9:1 ratio (passes AA), emerald-100/emerald-800 = 6.4:1 ratio (passes AA), violet-100/violet-800 = 6.8:1 ratio (passes AA)
