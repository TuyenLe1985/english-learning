# Phase 6: Listening Comprehension - Context

**Gathered:** 2026-06-15
**Status:** Ready for planning

<domain>
## Phase Boundary

Users can browse CEFR-filtered listening content (B1/B2/C1) by topic and content type (conversation, interview, podcast, lecture, news report), listen to audio with a sticky-header player (speed control at 0.75×/1×/1.25×/1.5×, section replay via transcript cue clicks), answer 3 exercise types after listening (IELTS-style: listen fully first, then answer), and after submitting receive an inline score card while the full transcript reveals with word-level karaoke sync active and tap-to-SRS enabled on every transcript word.

**Deliverables:**
- NestJS ListeningModule: endpoints for browse (filtered by CEFR/topic/contentType), item detail with exercises, session completion (stores ListeningProgress), word lookup (reuses existing VocabularyWord lookup from Phase 5)
- Listening pipeline: extends Phase 5's PipelineModule with ListeningCrawlerService (VOA + BBC + ESLPod + lecture/podcast sources, all 5 content types) + ListeningSeedService (download MP3 to MinIO/R2, Whisper forced alignment → wordTimestamps JSON, seed 200–300 items)
- Whisper Docker service: `whisper-worker` container in docker-compose.yml; pipeline calls it for forced alignment
- Next.js listening routes: `/listening` (browse + filter bar) → `/listening/[itemId]` (sticky player + locked/unlocked transcript + exercises + score card)
- `useAudioPlayer()` React hook: manages currentTime, duration, playbackRate, isPlaying; drives karaoke sync
- 3 exercise components: MultipleChoice (reuse from Grammar/Vocabulary), FillMissingWords, Dictation
- Tap-to-SRS on transcript words: reuses Phase 5's WordPopover component and POST /api/srs/enroll

</domain>

<decisions>
## Implementation Decisions

### Transcript Synchronization
- **D-01:** **Word-level karaoke highlighting**: Each individual word in the transcript highlights as it is spoken during playback. All other words remain unhighlighted. The active word auto-scrolls into view.
- **D-02:** **Whisper forced alignment for word timestamps**: Word-level timestamps are generated by running openai/whisper (or faster-whisper) on each audio file during the pipeline. Timestamps are not sourced from WebVTT cue files (which are sentence-level), so all sources yield the same word-level precision regardless of whether the source provides subtitle files.
- **D-03:** **Pipeline flow: download → Whisper → store**: Audio pipeline step sequence: (1) download MP3 from source, (2) upload to MinIO/R2, (3) call whisper-worker Docker service for forced alignment, (4) receive `[{word, start, end}]` JSON, (5) store in `wordTimestamps` DB column alongside transcript text.
- **D-04:** **`wordTimestamps: Json` column on ListeningItem**: Word timestamps stored as a `Json` Prisma type column on the `ListeningItem` model — array of `{ word: string, start: number, end: number }` objects (times in seconds). One DB read fetches audio URL, transcript text, and timestamps together. No separate TranscriptWord table, no external file in R2.

### Audio Content Source + Pipeline
- **D-05:** **Crawl sources with public audio + transcripts**: Sources — VOA Learning English (news reports + educational), BBC Learning English (conversations + interviews), ESLPod or equivalent (podcast/conversational content), and a lecture source (e.g., TED-Ed or open courseware) for the lecture content type. All 5 content types from LIST-01 must be represented in the seeded corpus.
- **D-06:** **200–300 items seeded before first deploy**: ~50–100 items per CEFR level (B1/B2/C1). Seed run budget: ~30 min on CPU-only Whisper. Storage: ~300 MP3s × ~3 MB avg = ~900 MB in MinIO/R2. Acceptable for a portfolio-scale deployment.
- **D-07:** **Extend Phase 5's PipelineModule**: Add `ListeningCrawlerService` and `ListeningSeedService` to the existing `apps/api/src/pipeline/` module. Same `NestFactory.createApplicationContext()` CLI entry point. New pnpm scripts: `pipeline:crawl:listening`, `pipeline:seed:listening`. `pipeline:validate:listening` for pre-bulk 20-URL sample validation.
- **D-08:** **All 5 content types from day one**: Corpus must include items tagged as `CONVERSATION`, `INTERVIEW`, `PODCAST`, `LECTURE`, `NEWS_REPORT`. Researcher/planner must source one crawlable provider per type and include selector validation for each.

### Audio Player
- **D-09:** **Custom HTML5 `<audio>` + `useAudioPlayer()` hook**: No audio library (not Plyr, not Howler.js). Native `<audio>` element with a `useAudioPlayer()` custom hook managing `currentTime`, `duration`, `playbackRate`, `isPlaying`, `isSeeking`. Hook exposes `seek(time)`, `setSpeed(rate)`, `play()`, `pause()`. Player UI built with shadcn/ui Slider (seek bar) and Button components.
- **D-10:** **Transcript-cue section replay**: Each transcript sentence/cue is a clickable element. Clicking any sentence calls `seek(cue.start)` and resumes playback from that timestamp. This is the "section replay" mechanism from LIST-03. Available in both locked mode (pre-exercise, limited replay) and unlocked mode (post-exercise, full replay). While locked: clicking a cue replays only that cue's range (`audioRef.currentTime = cue.start; audioRef.end = cue.end`). After unlock: free seek anywhere.
- **D-11:** **Sticky header player + scrollable transcript below**: Audio player controls are `position: sticky; top: 0` in the page layout. Transcript text scrolls below the sticky player. During playback, the active word auto-scrolls into view using `element.scrollIntoView({ behavior: 'smooth', block: 'center' })`. Desktop: transcript takes full width below player. Mobile: same stacked layout.
- **D-12:** **Speed toggle buttons in player bar**: Four pill-shaped toggle buttons displayed inline in the player controls bar: `0.75×` / `1×` / `1.25×` / `1.5×`. Active speed highlighted with a filled/accent state. Sets `audioRef.current.playbackRate`. No dropdown required.

### Exercise Flow
- **D-13:** **Listen-first flow (IELTS/TOEFL style)**: User listens to the full audio (or as much as desired — no forced completion gate). A visible "Start Exercises" button below the player activates after the audio reaches the 50% mark (prevents immediately skipping to exercises). Exercises appear below the player when activated. Transcript remains locked (blurred/hidden) throughout.
- **D-14:** **3 exercise types: MultipleChoice + FillMissingWords + Dictation**: (1) **MultipleChoice** — standard 4-option question reusing the Grammar/Vocabulary MC component. (2) **FillMissingWords** — a transcript sentence with one word blanked out; user selects from 3 options or types the word. Leverages the transcript text directly. (3) **Dictation** — play a short audio clip (5–10 seconds); user types what they hear. Checks against the transcript text with minor normalization (punctuation, case-insensitive). Each listening item must have at least one of each type to satisfy LIST-02.
- **D-15:** **Full transcript unlock together after submission**: After the user submits all exercises, the following happen simultaneously: (a) transcript text reveals (un-blurs), (b) word-level karaoke sync activates (current-time sync with audio), (c) cue-click section replay unlocks for full seek. All in one state transition — `transcriptLocked: false`. No separate "review mode" toggle needed.
- **D-16:** **Inline score card, stay on page**: Same pattern as Phase 5 D-04 (reading). After submission, a results card appears below the last exercise showing: score (X/Y questions), accuracy percentage, exercise-type breakdown, XP earned. No full-page redirect. User stays on the listening item page to review the unlocked transcript and tap words to SRS.

<specifics>
## Specific Ideas

- **Whisper Docker service**: Use `openai/whisper` or `faster-whisper` Docker image. Pipeline step: `POST http://whisper-worker:9000/align` with audio file path → returns `[{word, start, end}]`. faster-whisper is ~4× faster than openai/whisper on CPU and preferred.
- **`useAudioPlayer()` hook API**: `{ audioRef, currentTime, duration, isPlaying, playbackRate, play, pause, seek, setSpeed }`. `currentTime` drives karaoke — a `requestAnimationFrame` loop or `timeupdate` event finds the active word by binary search over `wordTimestamps`.
- **Karaoke active word detection**: Binary search `wordTimestamps` on every `timeupdate` event — `O(log n)` where n = word count. Highlight the word where `word.start <= currentTime < word.end`. Use a React ref for the active word span to call `scrollIntoView`.
- **FillMissingWords exercise**: Take a sentence from the transcript, blank out one vocabulary word (target CEFR B1–C1 vocab), present 3 distractor options. The exercise data is generated during the pipeline seeding step from the transcript text + CEFR word list.
- **Dictation exercise**: Clip a 5–10 second audio segment (using `audioRef.currentTime` seek + a small segment player). User types what they hear. Compare via Levenshtein distance ≤ 2 for minor typos (punctuation stripped, lowercase normalized).
- **Browse route**: `/listening?level=B2&topic=technology&type=news_report` — query params drive filters. NestJS: `GET /api/listening/items?cefrLevel=B2&topic=technology&contentType=NEWS_REPORT&page=1&limit=20`.
- **Locked transcript visual**: Transcript text shows as blurred (`filter: blur(4px)`) with a lock icon overlay. After unlock, blur animates out (`transition: filter 0.3s ease`). CSS-only, no conditional render needed.
- **"Start Exercises" gate**: Audio `timeupdate` tracks whether user has listened to ≥50% of the audio. Button activates (`disabled: false`) once this threshold is crossed. State stored in component: `hasListenedEnough: boolean`.

</specifics>

<deferred>
## Deferred Ideas

- **Recurring BullMQ pipeline for content refresh**: Like Phase 5's reading content, Phase 6 uses a one-time seed script. A scheduled BullMQ job for weekly audio content refresh is a post-v1 feature.
- **Speaker diarization**: Identifying which speaker is talking (for multi-speaker conversations). Whisper can do this but adds pipeline complexity. Deferred — Phase 6 karaoke sync is word-level without speaker attribution.
- **A–B loop repeat**: User-defined loop between two timestamp markers. Mentioned in gray area analysis as a language learning pattern (Anki-style). Deferred — transcript-cue replay covers the use case at lower complexity.
- **Adaptive difficulty for exercise generation**: Selecting exercise difficulty based on user's CEFR level to generate harder/easier dictation or fill-missing-words. Phase 8 (Adaptive Engine) handles difficulty routing.
- **Offline playback / Service Worker audio caching**: Caching audio files for offline use. Out of scope for v1 — app is online-first.

</deferred>
