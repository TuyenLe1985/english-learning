## Summary

Phase 6 builds on the complete Phase 5 infrastructure (PipelineModule, ReadingModule pattern, WordPopover, SRS enroll endpoint) and adds a listening comprehension workflow centered on three technical pillars: (1) a `whisper-worker` Docker service that generates word-level timestamps via faster-whisper's `word_timestamps=True` inference, (2) a custom HTML5 audio player hook with `requestAnimationFrame`-driven karaoke sync, and (3) a NestJS `ListeningModule` that mirrors `ReadingModule` exactly in structure.

The critical insight from research is that faster-whisper's built-in `word_timestamps` parameter — available without wav2vec2 forced alignment (that is WhisperX's additional layer) — produces the `[{word, start, end}]` JSON directly. The `hwdsl2/whisper-server` Docker image exposes an OpenAI-compatible REST API on port 9000, accepting `POST /v1/audio/transcriptions` with `timestamp_granularities[]=word` and returning a `words` array — zero custom server code required.

The schema migration is minimal: one `ALTER TABLE "ListeningContent" ADD COLUMN "wordTimestamps" JSONB` statement. The `ListeningContent`, `ListeningQuestion`, and `ListeningProgress` models already exist in the Prisma schema. The `wordTimestamps` column is the only addition Phase 6 needs. All ContentType enum values for listening (`CONVERSATION`, `INTERVIEW`, `PODCAST`, `LECTURE`, `NEWS_REPORT`) are already present in the schema.

**Primary recommendation:** Use `hwdsl2/whisper-server` (CPU, `base` model, `WHISPER_WORD_TIMESTAMPS=true`) as the whisper-worker service. Pipeline calls `POST http://whisper-worker:9000/v1/audio/transcriptions` with the MP3 file and receives a `words` array directly — no WhisperX or wav2vec2 alignment layer needed.

### Pattern 1: Whisper Worker HTTP Call (Pipeline)

```typescript
// Source: hwdsl2/docker-whisper API docs — OpenAI /v1/audio/transcriptions
// In ListeningCrawlerService (Node.js pipeline, uses FormData + fetch)
async function callWhisperWorker(
  audioPath: string,
): Promise<Array<{ word: string; start: number; end: number }>> {
  const form = new FormData();
  form.append('file', fs.createReadStream(audioPath), { filename: 'audio.mp3' });
  form.append('model', 'whisper-1');          // required field; value ignored by server
  form.append('response_format', 'verbose_json');
  form.append('timestamp_granularities[]', 'word');
  form.append('language', 'en');

  const response = await fetch('http://whisper-worker:9000/v1/audio/transcriptions', {
    method: 'POST',
    body: form,
    // No Authorization header — internal Docker network, no API key set
  });

  const json = await response.json() as {
    text: string;
    words: Array<{ word: string; start: number; end: number; probability: number }>;
  };

  return json.words.map(w => ({ word: w.word, start: w.start, end: w.end }));
}
```

### Pattern 2: useAudioPlayer Hook (requestAnimationFrame karaoke)

```typescript
// Source: MDN HTMLMediaElement.timeupdate + requestAnimationFrame documentation
// CRITICAL: Use requestAnimationFrame, NOT timeupdate, for karaoke sync.
// timeupdate fires at 4–66Hz (variable); rAF fires at ~60Hz (consistent).

'use client';
import { useRef, useState, useCallback, useEffect } from 'react';

export interface AudioPlayerState {
  currentTime: number;
  duration: number;
  isPlaying: boolean;
  playbackRate: number;
  hasListenedEnough: boolean;  // true once currentTime >= duration * 0.5
}

export function useAudioPlayer(audioUrl: string) {
  const audioRef = useRef<HTMLAudioElement | null>(null);
  const rafRef = useRef<number | null>(null);
  const [state, setState] = useState<AudioPlayerState>({
    currentTime: 0,
    duration: 0,
    isPlaying: false,
    playbackRate: 1,
    hasListenedEnough: false,
  });

  // rAF loop — runs while playing, reads currentTime at display refresh rate
  const startRafLoop = useCallback(() => {
    const tick = () => {
      if (!audioRef.current) return;
      const ct = audioRef.current.currentTime;
      const dur = audioRef.current.duration || 0;
      setState(prev => ({
        ...prev,
        currentTime: ct,
        hasListenedEnough: prev.hasListenedEnough || (dur > 0 && ct >= dur * 0.5),
      }));
      rafRef.current = requestAnimationFrame(tick);
    };
    rafRef.current = requestAnimationFrame(tick);
  }, []);

  const stopRafLoop = useCallback(() => {
    if (rafRef.current !== null) {
      cancelAnimationFrame(rafRef.current);
      rafRef.current = null;
    }
  }, []);

  const play = useCallback(() => { audioRef.current?.play(); }, []);
  const pause = useCallback(() => { audioRef.current?.pause(); }, []);
  const seek = useCallback((time: number) => {
    if (audioRef.current) audioRef.current.currentTime = time;
  }, []);
  const setSpeed = useCallback((rate: number) => {
    if (audioRef.current) audioRef.current.playbackRate = rate;
    setState(prev => ({ ...prev, playbackRate: rate }));
  }, []);

  return { audioRef, state, play, pause, seek, setSpeed, startRafLoop, stopRafLoop };
}
```

### Pattern 3: Binary Search for Active Karaoke Word

```typescript
// O(log n) — runs every rAF frame (~60fps); n = word count (typically 200–800)
// PERFORMANCE: Do NOT use setState for activeWordIndex inside rAF tick —
// use a ref to avoid triggering React re-renders at 60fps.
// Only update a data-active attribute on the word span element directly.

type WordTimestamp = { word: string; start: number; end: number };

function findActiveWordIndex(
  words: WordTimestamp[],
  currentTime: number,
): number {
  let lo = 0;
  let hi = words.length - 1;
  while (lo <= hi) {
    const mid = (lo + hi) >> 1;
    if (words[mid].end <= currentTime) {
      lo = mid + 1;
    } else if (words[mid].start > currentTime) {
      hi = mid - 1;
    } else {
      return mid;  // words[mid].start <= currentTime < words[mid].end
    }
  }
  return -1;  // between words (pause/silence)
}
```

### Pattern 4: FillMissingWords Exercise Generation (Pipeline)

```typescript
// Source: [ASSUMED] — based on CEFR word list already bundled in project (Phase 5)
// Run during ListeningSeedService, not at request time

function generateFillMissingWords(
  sentences: string[],         // from transcriptText split on sentence boundaries
  cefrWordList: Set<string>,   // B1–C1 vocabulary from cefr-word-list.json
): Array<{ prompt: string; answer: string; distractors: string[] }> {
  const exercises: Array<{ prompt: string; answer: string; distractors: string[] }> = [];

  for (const sentence of sentences) {
    const tokens = sentence.toLowerCase().match(/\b[a-z]+\b/g) ?? [];
    // Find a content word that is in the B1–C1 CEFR word list
    const targetToken = tokens.find(t => t.length >= 4 && cefrWordList.has(t));
    if (!targetToken) continue;

    // Blank the word in the original sentence (case-insensitive replace)
    const blanked = sentence.replace(new RegExp(`\\b${targetToken}\\b`, 'i'), '___');

    // Distractors: other CEFR words of similar length (+/- 2 chars)
    const distractors = pickDistractors(targetToken, cefrWordList, 3);
    if (distractors.length < 3) continue;

    exercises.push({ prompt: blanked, answer: targetToken, distractors });
    if (exercises.length >= 2) break;  // max 2 FillMissingWords per item
  }
  return exercises;
}
```

### Pattern 5: Dictation Scoring (Levenshtein with normalization)

```typescript
// Source: [ASSUMED] — standard dictation normalization pattern
import { distance } from 'fastest-levenshtein';

function normalizeDictation(text: string): string {
  return text
    .toLowerCase()
    .replace(/[.,!?;:"']/g, '')   // strip punctuation
    .replace(/\s+/g, ' ')          // collapse whitespace
    .trim();
}

function scoreDictation(
  userAnswer: string,
  correctAnswer: string,
): { isCorrect: boolean; distance: number } {
  const d = distance(normalizeDictation(userAnswer), normalizeDictation(correctAnswer));
  // Allow up to 2 character errors for minor typos (one missing/wrong letter)
  return { isCorrect: d <= 2, distance: d };
}
```

### Anti-Patterns to Avoid

- **Using `timeupdate` for karaoke:** Fires at 4–66Hz variable rate; causes visible highlight lag at lower rates. Use `requestAnimationFrame` instead. [VERIFIED: MDN]
- **Storing `wordTimestamps` in a separate TranscriptWord table:** D-04 locked this out. A JSON column on `ListeningContent` is one DB read vs. a join; for 200–300 items this is unambiguously faster.
- **Calling React `setState` inside rAF tick:** Will trigger React re-renders at 60fps and drop frames. Store `activeWordIndex` in a `useRef` and directly update DOM attributes via `wordRefs[idx].current?.setAttribute('data-active', 'true')`.
- **Re-generating presigned URLs on every component mount:** Cache the URL for the item page duration (it has 1-hour TTL). React Query's default stale time handles this.
- **Generating FillMissingWords exercises at request time:** Must be pre-generated during the seed pipeline and stored in `ListeningQuestion` rows, not computed on the fly.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Word-level audio timestamps | Custom forced alignment (CMU Sphinx, Kaldi) | `hwdsl2/whisper-server` with `WHISPER_WORD_TIMESTAMPS=true` | Kaldi/Montreal-forced aligner require phoneme dictionaries and model training; Whisper's built-in word timestamps work on any English audio with zero configuration |
| Levenshtein distance | `function editDistance(a,b)` | `fastest-levenshtein` | Edge cases: Unicode normalization, empty string inputs, buffer overflows in naive implementations |
| Audio storage with signed URL | Custom file server route streaming bytes | `@aws-sdk/s3-request-presigner` | Pre-signed URLs offload bandwidth from NestJS; browser streams directly from MinIO/R2; standard pattern already in project |
| JSON-to-word-span rendering | DOM manipulation | React map over `wordTimestamps` → `<span ref={wordRefs[i]}>` | React ref array on word spans is the standard pattern; direct DOM mutation via `document.getElementById` is not idiomatic in React 18 |

## Common Pitfalls

### Pitfall 1: whisper-worker returns transcript text but NOT word timestamps unless explicitly requested
**What goes wrong:** Pipeline receives a response with `text` but `words` is undefined or an empty array.
**Why it happens:** `WHISPER_WORD_TIMESTAMPS=true` enables word timestamps globally in the Docker env, OR you must pass `timestamp_granularities[]=word` AND `response_format=verbose_json` in the request. Missing either flag returns segment-level output only.
**How to avoid:** Set `WHISPER_WORD_TIMESTAMPS=true` in docker-compose.yml environment AND always pass `response_format=verbose_json` and `timestamp_granularities[]=word` in the FormData request.
**Warning signs:** `json.words` is undefined or `[]`; `json.segments` is populated instead.

### Pitfall 2: React setState at 60fps causes dropped frames
**What goes wrong:** Active word updates lag or the UI stutters during playback.
**Why it happens:** Calling `setState({ activeWordIndex })` inside the rAF loop triggers a full React re-render every 16ms.
**How to avoid:** Keep `activeWordIndex` in a `useRef`, not `useState`. Directly set `data-active="true"` on the word span DOM node. Only use state for coarse updates (play/pause/currentTime for seek bar — at lower frequency via `timeupdate`).
**Warning signs:** Chrome DevTools shows > 60 re-renders/sec in the Profiler; janky seek bar.

### Pitfall 3: Cue-replay locked mode boundary enforcement
**What goes wrong:** In locked mode (pre-exercise), user can seek past the cue boundary and hear later transcript sections.
**Why it happens:** HTML5 audio does not natively enforce end-time boundaries on seek.
**How to avoid:** In locked mode, attach a `timeupdate` listener that checks `audioRef.current.currentTime > cue.end` and resets to `cue.start` (or pauses). Remove this listener after unlock.
**Warning signs:** Users report hearing the transcript after a cue click goes past the cue end.

### Pitfall 4: whisper-worker `base` model accuracy for short audio clips (< 5 seconds)
**What goes wrong:** Word timestamps for dictation clips (5–10 seconds) have ±200ms error on short words.
**Why it happens:** Whisper was trained on 30-second segments; very short clips sometimes lose context. `base` model has ~5% WER overall but word boundaries can drift for short clips.
**How to avoid:** For dictation, pass a 10-second clip with 1–2 seconds of audio before and after the target segment, then use only the middle portion's timestamps. Or use a slightly larger model (`small`) for dictation clip alignment if accuracy is critical.
**Warning signs:** Karaoke word highlights are consistently 200–300ms behind the spoken word.

### Pitfall 5: ListeningContent `wordTimestamps` JSON is `null` for items with no Whisper run
**What goes wrong:** Karaoke sync component crashes on `wordTimestamps.map(...)` when the field is null (e.g., an item seeded without a Whisper run).
**Why it happens:** The column is nullable (`Json?`). Items seeded without a successful Whisper call will have `null`.
**How to avoid:** In the React transcript component, guard with `if (!wordTimestamps || wordTimestamps.length === 0) showStaticTranscript()`. In the NestJS response DTO, declare `wordTimestamps` as `Array<WordTimestamp> | null`.
**Warning signs:** `TypeError: Cannot read properties of null (reading 'map')`.

### Pitfall 6: Audio CORS — MinIO presigned URLs rejected by browser
**What goes wrong:** `<audio src={presignedUrl}>` fails with CORS error in browser.
**Why it happens:** MinIO dev bucket may not have CORS headers configured for the web origin (`http://localhost:3000`).
**How to avoid:** Add MinIO CORS config in the seed/setup script:
```bash
mc alias set local http://localhost:9000 minioadmin minioadmin
mc anonymous set-json '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Principal":"*","Action":["s3:GetObject"],"Resource":["arn:aws:s3:::audio/*"]}]}' local/audio
# OR set CORS rules via mc admin
```
Or use presigned URLs (CORS is already allowed for authenticated requests with presigned URLs from MinIO).
**Warning signs:** Browser Network tab shows OPTIONS preflight failing with 403 or missing `Access-Control-Allow-Origin`.

### Pitfall 7: Route ordering — fixed `sessions/complete` before param `:id` routes
**What goes wrong:** NestJS matches `POST /api/listening/sessions/complete` as `:id = "sessions"`.
**Why it happens:** NestJS matches routes in declaration order. Parameterized routes declared before fixed-string routes consume literal strings as param values.
**How to avoid:** Mirror the GrammarController pattern — declare `@Post('sessions/complete')` BEFORE `@Get(':id')` in ListeningController (same pattern as `grammar.controller.ts`).
**Warning signs:** `completeSession()` never called; `getItemById('sessions')` throws 404.

| ASVS Category | Applies | Standard Control |

### Known Threat Patterns for this Stack

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| IDOR on ListeningProgress | Spoofing | userId always from JWT; never trust body.userId; `completeSession` uses `req.user.userId` only |

| Large batch attacks on `completeSession` | DoS | `attempts` array bounded by question count per item (validate `attempts.length <= questions.length`) |
| Audio URL leakage (presigned URL forwarding) | Info Disclosure | 1-hour expiry on presigned URLs limits window; internal Docker network (MinIO not exposed publicly) |
| Injecting HTML into transcript | XSS | `transcriptText` rendered as text nodes (`{word.word}` in JSX span, not `dangerouslySetInnerHTML`); word spans are plain text |
