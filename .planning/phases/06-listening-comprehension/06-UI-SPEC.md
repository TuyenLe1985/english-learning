## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body (transcript) | 16px | 400 (regular) | 1.75 | Transcript prose text — `text-base leading-[1.75]` |
| Body (UI) | 14px | 400 (regular) | 1.5 | Labels, metadata, muted descriptions, question prompts |
| Label | 14px | 600 (semibold) | 1.4 | Section headers, card titles, exercise headers |
| Heading | 20px | 600 (semibold) | 1.2 | Listening item title on item page, section headings |
| Display | 28px | 600 (semibold) | 1.1 | Inline score card headline ("{score}/{total} correct") |

Notes:
- Transcript text uses `text-base` (16px) at `leading-[1.75]` — same line height as Phase 5 reading body but one size step smaller (18px → 16px) since karaoke word spans require tighter word-boundary precision. A 16px transcript at 1.75 line-height leaves adequate vertical space between highlight rows.
- Karaoke active word highlight does not change font size — it only changes background color and border-radius.
- Player control labels (time display, speed toggle labels) use `text-xs` (12px) at weight 400 — acceptable at this size because they are supplementary, not primary reading content.
- All prior phase typographic constraints preserved: max 2 weights (400, 600), `text-sm` for all non-special UI text.

#### 2c. Transcript panel

Position: below sticky player, within the scrollable page body.

Container: `relative mt-4 rounded-xl border border-border bg-card p-6`.

**Locked state** (pre-exercise submission, `transcriptLocked === true`):
- Transcript text is rendered (all word spans are in the DOM) but filtered: `filter: blur(4px)` via `className="blur-[4px] transition-[filter] duration-300 ease-in-out select-none pointer-events-none"`.
- Overlay: `absolute inset-0 flex flex-col items-center justify-center gap-3 bg-background/80 rounded-xl` — a semi-transparent overlay above the blurred text.
  - Lock icon: `LockKeyhole` Lucide icon at `size-8 text-muted-foreground` (32px).
  - Overlay label: `"Transcript is locked until you complete the exercises."` at `text-sm text-muted-foreground text-center max-w-[240px]`.
- Transcript-cue section replay in locked mode: individual transcript sentences are still rendered as `<button>` elements below the locked overlay — but they are `aria-disabled="true"` and visually hidden beneath the overlay. In locked mode, cue click is disabled (no `onClick` handler active).

**Unlocked state** (post-submission, `transcriptLocked === false`):
- Blur class removed: `filter: none`. The `transition-[filter] duration-300 ease-in-out` produces the blur-to-clear reveal animation.
- Lock overlay removed from DOM (conditional render `{transcriptLocked && <div>...overlay</div>}`).
- Word spans: `<span ref={wordRefs[i]} data-word-index={i} className="cursor-pointer rounded-sm px-0.5 transition-colors duration-75 hover:bg-muted/70">`. Each span wraps one word from `wordTimestamps`.
- Active word highlight (karaoke): the rAF loop sets `data-active="true"` on the active span and `data-active` is removed from all others. CSS rule in globals.css: `[data-active="true"] { background-color: hsl(var(--amber-200)); color: hsl(var(--amber-900)); border-radius: 0.125rem; }` — or via Tailwind `data-[active=true]:bg-amber-200 data-[active=true]:text-amber-900 data-[active=true]:rounded-sm`.
- Transcript-cue replay: each sentence `<div>` has `onClick={() => seek(cue.start)}` + `role="button"` + `tabIndex={0}` + hover `bg-muted/40 rounded-md px-1 cursor-pointer transition-colors`.
- WordPopover: each word span in unlocked transcript has `onClick={() => openPopover(word, contextSentence)}`. Reuses Phase 5 `WordPopover` component directly.
- Auto-scroll: when `activeWordIndex` changes, `wordRefs[activeWordIndex].current?.scrollIntoView({ behavior: 'smooth', block: 'center' })`.
- Fallback (no `wordTimestamps`): if `wordTimestamps` is null or empty, render transcript as plain `<p>` text without word spans or karaoke. Show `"Karaoke sync unavailable for this item."` at `text-xs text-muted-foreground` below the transcript.

Transcript section header: `text-sm font-semibold text-foreground mb-3` — "Transcript". Appears above the transcript container.

## Karaoke Interaction Contract

This section specifies the exact visual and performance contract for karaoke word highlighting.

### Word span structure

Each word in the transcript renders as:

```tsx
<span
  ref={wordRefs[i]}
  data-word-index={i}
  data-active="false"
  className={cn(
    "cursor-pointer rounded-sm px-0.5 transition-colors duration-75",
    "hover:bg-muted/70",
    "data-[active=true]:bg-amber-200 data-[active=true]:text-amber-900",
  )}
  onClick={() => openWordPopover(word.word, getSentenceContext(i))}
  onKeyDown={(e) => { if (e.key === 'Enter' || e.key === ' ') openWordPopover(...) }}
  role="button"
  tabIndex={0}
  aria-label={`Word: ${word.word}`}
>
  {word.word}
</span>{' '}
```

The trailing `{' '}` renders the inter-word space outside the span, preventing highlight bleed between adjacent words.

### Performance model

- `data-active` attribute set/unset directly via `wordRefs[i].current?.setAttribute('data-active', 'true')` — NOT via React `setState`. This bypasses React's reconciler at 60fps.
- The rAF loop only calls `scrollIntoView` when `activeWordIndex` actually changes (compare to previous frame's index stored in `prevActiveRef`).
- `scrollIntoView({ behavior: 'smooth', block: 'nearest' })` — `nearest` preferred over `center` to minimize scroll distance when the active word is partially visible.
- Transition duration on word spans: `duration-75` (75ms) — fast enough to feel instantaneous at speech speeds, slow enough to avoid a strobe effect.

### Fallback when `wordTimestamps` is null

- Transcript renders as plain `<p className="text-base leading-[1.75] text-foreground">` with no word spans.
- Karaoke indicators omitted entirely.
- WordPopover not available (no word spans to tap).
- Transcript-cue replay unavailable (no sentence-level timestamp data).
- Static transcript text remains readable.
- Banner: `text-xs text-muted-foreground italic mt-2` — `"Word-level sync is unavailable for this item."`.

## Transcript Lock / Unlock Visual Contract

| State | CSS | User Interaction |
|-------|-----|-----------------|
| Locked (pre-submit) | `filter: blur(4px)` on transcript text; `pointer-events-none select-none` | None — overlay covers text |
| Unlocking (300ms transition) | `filter: blur(4px) → blur(0px)` via `transition-[filter] duration-300 ease-in-out` | Visible animation |
| Unlocked (post-submit) | No filter applied; word spans interactive | Tap-to-SRS, cue replay |

The lock overlay (`absolute inset-0 bg-background/80`) is conditionally rendered (`{transcriptLocked && ...}`). Removing it from the DOM is the trigger for the filter transition — the underlying transcript text already has `transition-[filter]` applied, so removing the filter class causes the animated reveal.

## Accessibility Contract

- All transcript word `<span>` elements in unlocked mode: `role="button"` + `tabIndex={0}` + `onKeyDown` (Enter/Space triggers WordPopover).
- Locked transcript: `aria-hidden="true"` on the blurred text div — screen readers should not announce blurred/decorative content.
- Lock overlay: `role="status"` + `aria-live="polite"` — announces lock state change when transcript unlocks.
- Audio player seek bar (shadcn Slider): `aria-label="Audio seek bar"` + `aria-valuenow={currentTime}` + `aria-valuetext="{formatted time}"` + `aria-valuemin={0}` + `aria-valuemax={duration}`. shadcn Slider passes these through via `...props`.
- Speed toggle group: `<div role="group" aria-label="Playback speed">`. Each speed button: `aria-pressed={isActive}`.
- Play/Pause button: `aria-label` switches between `"Play"` and `"Pause"` dynamically.
- Exercise option buttons: `aria-pressed` or `aria-selected` reflects answered state. Disabled options: `aria-disabled="true"`.
- Dictation Textarea: `aria-label="Type what you hear"`. After reveal: `aria-describedby="{id-of-feedback-element}"`.
- "Start Exercises" button when disabled: `aria-disabled="true"` + `title="Listen to at least 50% of the audio first"` for tooltip discovery.
- Score card: `role="region" aria-label="Exercise results"` — announces to screen readers after reveal.
- Touch targets: all interactive elements minimum 44×44px (`min-h-[44px]`). Word spans in transcript: `min-h-[24px]` is acceptable as tapping inline words is a discovery interaction, not a primary navigation action.
- CEFR badges: existing `role="img"` + `aria-label` from `CefrBadge` — unchanged.
