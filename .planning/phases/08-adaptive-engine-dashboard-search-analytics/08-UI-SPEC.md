## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, heatmap cell gap, search tag chips |
| sm | 8px | Within card internals, label-to-value gaps, chart legend row gaps |
| md | 16px | Default card padding, chart container padding, search result item padding |
| lg | 24px | Between dashboard grid sections, between search result groups |
| xl | 32px | Between major page sections (hero → two-column grid → horizontal rows) |
| 2xl | 48px | Page-level vertical rhythm on analytics and admin pages |
| 3xl | 64px | Not used in Phase 8 |

Exceptions:
- Dashboard hero card: `p-6` (24px) inner padding — wider than default card to give XP bar breathing room
- Horizontal scroll rows: `gap-4` (16px) between scroll item cards; `pb-4` (16px) scroll gutter
- Activity heatmap grid cells: `gap-[3px]` (not a full 4px token) — standard GitHub heatmap visual density
- Search input in top nav: `h-9` (36px) height — matches existing top nav button sizing
- Touch targets on Continue Learning CTA and skill score items: minimum `min-h-[44px]`
- Admin/student analytics chart containers: `min-h-[200px]` to prevent empty-state layout collapse

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `hsl(0 0% 100%)` — `--background` | Page background, dashboard surface, search page background |
| Secondary (30%) | `hsl(240 4.8% 95.9%)` — `--secondary` / `--card` | All cards (hero card, skill score card, search result cards, analytics chart containers, admin stat cards) |
| Accent (10%) | `hsl(240 5.9% 10%)` — `--primary` | Reserved for specific elements listed below |
| Destructive | `hsl(0 84.2% 60.2%)` — `--destructive` | No destructive actions in Phase 8 |

Source: `apps/web/src/app/globals.css` — zinc CSS variable tokens; dark mode values defined.

**Accent reserved for:**
1. XP progress bar fill in dashboard hero (shadcn `Progress` component fill)
2. Continue Learning CTA button ("Start Lesson" / "Work on [Skill]")
3. Search submit button and active filter chips (`bg-primary text-primary-foreground`)
4. Recharts chart lines for the primary data series (CEFR progression LineChart active line, weekly bar chart active bar)
5. Active sidebar nav link indicator (left border or background)
6. "Show more →" links in search result sections

**Chart semantic colors (use `--chart-*` CSS variables from globals.css, not arbitrary colors):**
- `--chart-1` (`12 76% 61%` warm orange): Recharts BarChart — daily activity bars
- `--chart-2` (`173 58% 39%` teal): Recharts LineChart — CEFR progression primary line
- `--chart-3` (`197 37% 24%` dark blue): Recharts LineChart — vocabulary retention line
- `--chart-4` (`43 74% 66%` gold): Recharts BarChart — learning time bars
- `--chart-5` (`27 87% 67%` amber): AdminDashboard — user growth chart line

**Activity heatmap intensity colors (GitHub-style):**
- 0 activity: `bg-muted` (hsl(240 4.8% 95.9%))
- 1–3 exercises: `bg-emerald-200`
- 4–7 exercises: `bg-emerald-400`
- 8+ exercises: `bg-emerald-600`

**CEFR badge semantic colors (inherited from CefrBadge component — do not override):**
- B1: `bg-blue-100 text-blue-700 border-blue-200`
- B2: `bg-emerald-100 text-emerald-800 border-emerald-200`
- C1: `bg-violet-100 text-violet-800 border-violet-200`

**Weak skill indicator:**
- `isWeak = true` skill scores: `text-destructive` value + `bg-destructive/10` card background tint
- Recovered skill scores: normal foreground, no tint

## Screen Inventory

### Screen 1: Dashboard (`/dashboard`) — replaces placeholder

**Layout:** Full-width within `max-w-screen-xl` container established by dashboard layout. No nested max-width constraint — hero spans the full content width.

**Hero section (D-01):** Single full-width `Card` with `p-6`. Contains:
- Row 1: User greeting "Welcome back, {name}" at 20px semibold + `LevelBadge` (md size) + `CefrBadge` — all inline, `gap-3`
- Row 2: `XpProgressBar` — full width, reused component
- Row 3: Streak flame `Flame` icon (lucide, 18px, `text-orange-500`) + "{n} day streak" at 14px semibold + `text-muted-foreground` label "Keep it up!" inline

**Two-column grid (D-02):** `mt-6`, CSS grid `grid grid-cols-1 md:grid-cols-2 gap-6` below hero.
- Left column: `SkillScoresCard` on top (fixed height `min-h-[240px]`), `SkillRadarChart` below (`min-h-[220px]`)
- Right column: `ActivityBarChart` on top (`min-h-[220px]`), `ContinueLearningWidget` below (auto height, `min-h-[120px]`)

**Horizontal scroll rows (D-04):** `mt-6`, two rows stacked vertically with `gap-6`. Each row:
- Row heading at 16px semibold + "View all →" link (`text-sm text-primary`) — `flex justify-between items-center mb-3`
- `ScrollArea` with horizontal scrolling, `pb-4`, cards `w-[200px] flex-shrink-0`

**Loading state:** All cards replaced by `Skeleton` with matching dimensions. Hero: 1 full-width skeleton block `h-[120px]`. Grid: 4 skeleton blocks matching card heights.

**Empty state — no skill data yet:** `SkillScoresCard` shows 4 skill rows with `—` value and `text-muted-foreground` instead of `text-destructive`. No isWeak indicators until first session completed.

**Empty state — no recently viewed:** "Start a lesson to see your recent activity here." — `text-sm text-muted-foreground` centered in the scroll row area. No scroll area rendered.

**Empty state — no bookmarks:** "Bookmark lessons and passages to find them here quickly." — same treatment as recently viewed.

### Screen 4: Search Results (`/search`)

**Layout:** Centered column, `max-w-3xl mx-auto`. Page heading "Search results for "{query}"" at 20px semibold. Result count: `text-sm text-muted-foreground` "{n} results across {m} categories".

**Filter bar:** `SearchFilters` component below heading. Three filter groups, each as a `Select`:
- CEFR Level: All / B1 / B2 / C1
- Topic: All / (dynamic list from results)
- Skill: All / Grammar / Vocabulary / Reading / Listening

Active filters shown as dismissible `Badge` chips (`variant="secondary"`, `×` dismiss button). "Clear all" link if any filter active.

**Result groups (D-10):** Sections in order: Vocabulary · Grammar · Reading · Listening · Quiz. Each group:
- Section header: `Separator` + module name at 16px semibold + `Badge variant="secondary"` with count
- 3–5 `SearchResultItem` cards, each with:
  - Title at 14px semibold
  - `CefrBadge` + topic `Badge variant="outline"` — inline row
  - `ts_headline` snippet at 14px regular, matched terms wrapped in `<mark>` styled `bg-yellow-100 text-yellow-800 rounded-sm px-0.5`
  - Content type label at 12px muted (e.g. "Grammar Lesson", "Reading Passage")

**No results state:** `Search` icon (lucide, 48px, `text-muted-foreground`) centered + "No results for "{query}"" at 20px semibold + "Try adjusting your filters or search with different keywords." at 14px muted + "Clear filters" Button (outline variant).

**Activity heatmap detail:** `react-activity-calendar` or custom CSS grid `grid grid-cols-[repeat(52,1fr)] gap-[3px]`. Each cell: `w-3 h-3 rounded-sm`. **Empty state — no activity:** Heatmap renders with all cells `bg-muted`. No special message needed — empty grid is self-explanatory with legend.

## Interaction Contract

### Dashboard Data Loading

- All dashboard data fetched client-side via React Query `useQuery` hooks — no blocking SSR
- Initial render: all cards show `Skeleton` placeholders
- Hero loads first (single `/api/dashboard/summary` endpoint call)
- Two-column grid data loads in parallel (skill scores + activity in same or separate queries)
- Horizontal rows load last (recently viewed + bookmarks deferred with `staleTime: 60000`)
- On error: affected cards show inline error message with retry button; rest of dashboard remains visible

### Continue Learning Widget State Machine

```
LOADING → PRE_THRESHOLD (< 5 exercises) | WEAK_TOPIC_FOUND | ALL_HEALTHY
```

- Threshold check is server-side (`AdaptiveService.getContinueLearningRecommendation`)
- Widget receives a single recommendation object from API; no client-side logic for tier selection
- CTA navigation: `router.push('/[module]')` or `/quiz` depending on recommendation type

### Search Interaction

- Enter key or click on search icon submits
- URL updates to `/search?q={query}` — React Query fetches on mount
- Filter changes update URL query params (`router.push` with updated params) — triggers React Query refetch
- No debounce on search input in top nav (submit-only, not live search)
- "Clear filters" resets all query params except `q`
- "Show more" navigates to `/search?q={query}&skill={skill}` (pre-filtered to that section's module)

### Analytics Time Range Toggle

- Recharts `LearningTimeChart` has a `Select` control (Daily / Weekly / Monthly)
- Selection updates local React state — no URL param change
- Chart data refetches via React Query with new time range param
- Default selection: "Weekly"

### Admin Role Gate

- `apps/web/src/app/(dashboard)/admin/page.tsx` is a Server Component
- Server-side check: `session.user.role !== 'ADMIN'` → `redirect('/dashboard')`
- Sidebar admin link: `{session?.user?.role === 'ADMIN' && <NavLink href="/admin" .../>}`
- No client-side role enforcement — all role logic at server/API level

### Accessibility

- Search input: `role="search"` on wrapping `<form>`, `aria-label="Search platform content"` on input
- Heatmap: `role="grid"`, `aria-label="Activity over the past year"`, each cell has `aria-label="{n} exercises on {date}"`
- Analytics charts: each chart `Card` has `aria-label="{chart name} chart"` — Recharts does not provide this by default
- Admin stat cards: `<dl>` with `<dt>` label and `<dd>` value for screen reader stat announcement
- Skill scores: `isWeak` rows include `aria-label="{Skill}: {accuracy}% — needs improvement"`
- Continue Learning CTA: `aria-label="Continue learning: {skill area or module name}"`
- Sidebar nav links: `aria-current="page"` on active link
